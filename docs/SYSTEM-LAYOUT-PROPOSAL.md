# Personal OS: служебное внутри system

> Проект подготовлен ИИ-агентом по материалам обсуждения. Структура реализована в рабочей ветке; поведенческие уточнения — следующий отдельный шаг.

В корне видны личные материалы, проекты и одна служебная папка. Внутри
`system/` структура может быть подготовлена сразу: пользователю не требуется
изучать её для обычной работы, агент раскрывает нужную часть по ссылкам.

Это проект для обсуждения на базе v0.3.1 (`b20ea1d`). В этой ветке выполнен перенос `workspace/`, обновлены пути, карты,
онбординг и ссылки клиентов. Основная ветка и личные установки не менялись.
Поведенческие уточнения ниже пока не внесены. Новые модельные эксперименты
не запускались; эта структура ещё не проверена агентами.

## Предлагаемая установленная папка

Все файлы и папки в следующем дереве создаются **сразу при новой установке**.
Вложенные папки по реальным задачам показаны отдельно ниже.

```text
<выбранный корень OS>/
├── README.md                  Карта личных материалов и служебного раздела
├── AGENTS.md                  Вход агента, фактические ОС, корень и оболочка
├── LICENSE
├── .gitignore
├── personal/
│   ├── INDEX.md
│   ├── profile.md
│   ├── preferences.md
│   └── inbox/
│       └── README.md
├── projects/
│   └── INDEX.md
└── system/
    ├── INDEX.md               Карта служебных областей, не полные инструкции
    ├── agent/
    │   ├── INDEX.md
    │   ├── BOOTSTRAP.md
    │   ├── identity.md
    │   ├── memory.md
    │   └── protocols/
    │       └── handoff.md
    ├── tools/
    │   └── INDEX.md
    ├── skills/
    │   └── INDEX.md
    ├── infra/
    │   └── INDEX.md
    ├── docs/
    │   ├── INDEX.md
    │   ├── WORKING-RULES.md
    │   └── templates/
    │       ├── note.md
    │       ├── project.md
    │       └── tool.md
    ├── secrets/
    │   └── README.md          Только политика; значения секретов вне OS
    └── temp/
        └── README.md
```

Базовый набор сохраняет 25 файлов, но в корне остаются 3 папки вместо 9
и 4 файла вместо 5. Корневая карта `INDEX.md` уступает место карте в `README.md`;
`system/INDEX.md` описывает только служебные маршруты. Лицензия сохраняется.
Папка `secrets/` тоже переезжает под `system/` и содержит только политику,
не значения ключей. Системная инфраструктура относится к `system/infra/`;
пользовательские документы об устройствах — к личной области.

Дерево описывает личную установку, не исходный репозиторий. Продуктовый README,
отдельный агентский онбординг и каталог инструкций для клиентов сохраняются
в исходном комплекте. Они не копируются в личную OS целиком.

## Что появляется позже

Это предусмотренные инструкциями места роста, а не папки, которые нужно
создать заранее. Имена в угловых скобках — обозначения; буквальные папки
`<проект>` или демонстрационные проекты не создаются.

| Путь | Когда появляется | Где агент находит правило |
|---|---|---|
| `personal/<тема>/` | Когда несколько связанных материалов требуют своей области; для одной заметки обычно достаточно файла | `personal/INDEX.md`, общие рабочие правила |
| `projects/<проект>/` | Для реальной самостоятельной задачи с состоянием и артефактами | `projects/INDEX.md`, форма проекта |
| `system/tools/<возможность>/` | При документировании реально нужного инструмента или процедуры | `system/tools/INDEX.md`, форма инструмента |
| `system/skills/<навык>/` | При добавлении выбранного переносимого пакета или тонкого входа к собственной процедуре | `system/skills/INDEX.md` |
| `system/infra/<система>/` | При появлении конкретного устройства или сервиса, требующего эксплуатационных записей | `system/infra/INDEX.md` |
| `system/temp/<задача>/` | Если текущая работа требует временных файлов | `system/temp/README.md` |
| Каталоги конкретного клиента | Только если выбранному клиенту нужен свой путь обнаружения или адаптер; вне `system/` — лишь при таком требовании | Каталог клиентов и инструкция выбранного клиента |

Раздел `system/secrets/` не предусматривает появления файлов со значениями
секретов. Допустимы правила и несекретные ссылки на согласованное внешнее
хранилище. Не создавать отдельную папку или новый INDEX для каждого документа:
добавить маршрут в ближайшую существующую карту достаточно.

## Вход и рост

Агент начинает с корневого `AGENTS.md`, проверяет локальную среду и читает
`system/agent/BOOTSTRAP.md`. Корневой README и карта `system/INDEX.md` ведут
к нужной области. Роль, компактная память и предпочтения остаются короткими;
инструменты, навыки, инфраструктура и справочники читаются по задаче.

Корень может быть любым, включая корень диска. Соседние папки не становятся
частью OS автоматически. Все внутренние ссылки относительные. Совпадение
имени `system/` с существующей чужой папкой требует разрешения конфликта,
а не перезаписи или присвоения её содержимого.

Подготовленные служебные папки не означают установленных возможностей.
Новая заметка обычно остаётся одним файлом в подходящей области. Отдельный
проект появляется, когда нужна самостоятельная задача с состоянием,
решениями или артефактами; для каждой установки навыка проект не обязателен.

## Предлагаемые уточнения правил

Это гипотезы исправлений, а не обещание устранения ошибок без повторной проверки.
Каждое уточнение следует внести в один документ-владелец, а из остальных дать
ссылку; не размножать весь список по картам и инструкциям клиентов.

| Ситуация | Требуемое поведение | Владелец правила |
|---|---|---|
| Работа продолжится в другом чате | Сохранить сам значимый результат: полный черновик, решение или план. Запись «черновик готов» не заменяет его текст. Исключения: явная просьба не сохранять и правила чувствительных данных | `system/agent/protocols/handoff.md` |
| Появился новый документ | Добавить маршрут в ближайшую карту; в памяти — только необходимую ссылку для продолжения. Сохранение файла без маршрута не завершает передачу | `system/docs/WORKING-RULES.md` |
| Нужен собственный skill для существующей процедуры | Тонкий вход: когда применять и где читать процедуру. Не добавлять второй алгоритм или вторую реализацию команды | `system/skills/INDEX.md` |
| Навык применён к личной или проектной задаче | Итог встречи, письмо или анализ сохраняется по владельцу задачи в `personal/` либо `projects/`. Документация инструмента и временный каталог не становятся хранилищем результата | `system/tools/INDEX.md` |
| Записывается вывод проверки | Разделять наблюдение, предположение и непроверенное. Наличие файла, успешная загрузка текущим клиентом и обнаружение новой сессией — разные проверки | `system/docs/WORKING-RULES.md` |
| Заполняется новая OS | Убирать противоречащие новым данным фразы-заглушки; неизвестные версии и характеристики не угадывать | Онбординг |

Для создаваемого `SKILL.md` нужен короткий пример корректного YAML с
`name` и `description`, включая безопасное оформление двоеточий. Формат
нужно проверять доступным штатным загрузчиком; установка Python или другого
runtime ради этого не становится условием стартера. Исходник внешнего пакета
не переписывается под собственные метаданные OS.

## Решение, которое нельзя свести к переносу папок

Общее хранение навыков и их автоматическое обнаружение клиентом — разные
механизмы. Предлагается хранить самостоятельно добавленные переносимые
пакеты в `system/skills/<name>/` с лицензией и ресурсами; клиентские входы
добавлять по необходимости. Пакеты, управляемые самим клиентом или плагином,
остаются у их установщика и получают маршрут из общей карты.

Нельзя обещать, что произвольный клиент сам прочитает `system/skills/`.
Если нужен специальный каталог или адаптер, его подключение проверяется
отдельно. Не вводить обязательные symlink, копии алгоритмов или глобальную
настройку всех клиентов. При отсутствии обнаружения агент может прочитать
каноническую инструкцию явно, честно отметив границу автоматического подключения.

## После обсуждения

1. Зафиксировать выбранную структуру и правило хранения/подключения навыков.
2. Внести переносы отдельно от поведенческих уточнений, чтобы видеть обе
   группы изменений. Обновить ссылки, `.gitignore`, примеры и онбординг;
   не мигрировать существующие личные установки автоматически.
3. Для ветки указывать её точную ревизию: действующий онбординг закреплён
   за v0.3.1 и иначе скачает старый вариант. Сохранить и Git, и ZIP-маршрут.
4. После решения владельца запустить новое исследование на чистых папках.
   Отдельно проверить влияние переноса и изменения инструкций; в сценариях
   менять только необходимые пути, не подсказывая правильное поведение.
5. Особое внимание: сохранение полного результата между сессиями, разные
   модели при передаче, выбор области для результата, skill-адаптеры,
   Windows без Python и повторный вход в уже заполненную OS.

В этой ветке не размещаются частные рабочие области, исходные трассы,
учётные данные или личная история. Ошибки выполнения кода, выдуманные факты
и зацикливание не считаются исправленными сменой структуры каталогов.
