# Подключение клиента

Сначала откройте созданную OS как рабочую папку/проект клиента и передайте агенту:

```text
Канонический корень этой Personal OS: <ABSOLUTE_OS_ROOT>.
Прочитай INDEX.md, AGENTS.md и agent/BOOTSTRAP.md из этого корня.
Дальше раскрывай только область текущей задачи.
```

Замените `<ABSOLUTE_OS_ROOT>` фактическим абсолютным путём.
Такой явный вход работает без предположений об автоматическом discovery файлов.
Если у клиента нет доступа к пути, дайте ему разрешение штатным способом или
передайте выбранные несекретные документы. Не заявляйте о чтении недоступных файлов.

## Постоянный указатель

У клиентов различаются правила пользовательских/проектных инструкций, доверия,
MCP и навыков. Перед настройкой определите клиент и версию, прочитайте его
актуальные официальные инструкции или локальную справку. Это относится к Codex,
Claude Code, OpenCode, BB и другим оболочкам; шаблон не устанавливает их.

В штатный стартовый файл поместите короткий указатель, а не копию всех правил.
Если такой файл уже существует, сохраните его содержание и добавьте узкий блок.
Предварительно покажите конкретный diff и область действия владельцу: глобальный
указатель будет влиять и на другие проекты этого профиля клиента.
Для общего компьютера выбирайте отдельные учётные записи/профили людей,
а не общий глобальный указатель на одну из семейных OS.

[clients/entrypoint.example.txt](../clients/entrypoint.example.txt) — только образец
текста, его нельзя устанавливать с незаменённым путём. В новой OS
`docs/CLIENT-ENTRYPOINT.txt` уже содержит фактический путь.

## Проверка новой сессии

Создайте новый чат через обычный интерфейс клиента. Передайте ему короткое
поручение из [приёмки](ACCEPTANCE.md). Успех — фактическое нахождение канонических
файлов и чтение правил, а не существование указателя на диске. Запишите client,
версию, способ входа и результат в `docs/SETUP.md` новой OS.
Поведение другого клиента и другой модели проверяйте отдельно.
