# Устройство

Personal OS хранит проверяемый контекст на диске. Клиент и модель могут меняться;
файлы, решения и точки продолжения остаются у владельца.

## Два разных дерева

`personal-os-starter/` — публичный продукт: инструкции, исходники и установщик.
`workspace/` внутри него — нейтральные файлы с подстановками `{{...}}`.
Созданная `personal-os/` — отдельная приватная рабочая область с собственной жизнью.
У неё нет общей Git-истории или автоматически настроенного remote с шаблоном.

## Один источник каждого факта

Профиль владельца — `personal/profile.md`, общение — `personal/preferences.md`.
Рабочая роль агента — `agent/identity.md`, компактная непрерывность — `agent/memory.md`.
Текущий статус задачи — в проекте; общая память ссылается на него, не дублирует.
Процедура инструмента — в `tools/<capability>/README.md`. Карты содержат маршруты,
а не второй набор инструкций. Исполняемый код живёт в отдельном `code_root`.

## Загрузка по необходимости

`INDEX.md` → корневые правила → `agent/BOOTSTRAP.md` → карта нужной области →
документ задачи → только необходимые справочники. Полную память, входящие,
почту, библиотеку навыков и архивы не загружают на каждом старте.
Подробный опыт можно добавлять позже в `agent/memory/`, связав с коротким входом.
Новые области создаются по наблюдаемой задаче, а не на случай будущего роста.

## Переносимость

Ядро — UTF-8 Markdown, JSON и относительные ссылки, без скрытой базы данных.
Редактор необязателен. Подключение к клиенту — короткий указатель на канонический
корень. Автообнаружение инструкций и доступность tools проверяются отдельно.
Работающий локально агент может отправлять прочитанный контекст своему облачному
провайдеру: локальное хранение само по себе не означает локальную обработку.

## Что настраивается заново

Владелец и его предпочтения, имя/стиль агента, пути, язык и часовой пояс.
Модель, подписки, коннекторы, scopes, бюджеты, расписания и аккаунты выбираются
отдельно; шаблон не даёт им разрешений и не назначает предпочтительную модель.
