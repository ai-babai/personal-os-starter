# Подключения после ядра

Пустой каталог `tools/` не означает, что установлен инструмент. Сначала выберите
задачу, потом подходящий доступ. Комплект не содержит внешних навыков,
приватных API-шлюзов, готовых аккаунтов, OAuth-сессий и обещаний бесплатного доступа.

| Возможность | Что выбрать отдельно | Первая проверка |
|---|---|---|
| Интернет | Поиск клиента или браузерный инструмент | Открыть публичную страницу |
| Почта | Коннектор выбранного почтового сервиса | Список разрешённых папок без тел писем |
| Telegram | Личный клиент либо бот; это разные доступы | Проверить собственный аккаунт/бота и точного получателя |
| Аудио → текст | Локальное распознавание либо разрешённый API | Синтетическая запись с известным текстом |
| Текст → аудио | Локальный движок либо разрешённый API | Одна короткая фраза в пределах согласованного бюджета |
| Документы | Нужный редактор/skill с лицензией | Синтетический документ без личных данных |

Для каждого выбранного подключения:

1. Согласуйте аккаунт, scopes, доступные действия и бюджет. Начинайте с чтения,
   когда оно достаточно. Не назначайте отправку/удаление по умолчанию.
2. Установите официальный пакет по его действующим инструкциям; зафиксируйте
   источник, версию, лицензию и способ удаления. Не переносите venv, абсолютные
   symlink или auth-файлы другого человека.
3. Учётные данные владелец вводит в защищённом интерфейсе; значения вне OS/Git.
   В `secrets/` остаётся только политика, при необходимости — не секретная ссылка.
4. Создайте инструкцию в `tools/<capability>/README.md` и маршрут в `tools/INDEX.md`.
   Используйте [форму](../workspace/docs/templates/tool.md) как исходник.
5. Разделяйте «документировано», «установлено», «аутентифицировано», «проверено».
   Запишите фактический вызов и ограничения, не объявляйте всё готовым по `--help`.
6. Добавьте нужный skill только если это помогает текущей задаче или discovery.
   Собственную процедуру храните в одном месте. Системные/plugin-managed пакеты
   оставляйте установщику клиента; чужие лицензии сохраняйте.

Сообщения, платежи, публикация и live-изменения сохраняют свои границы разрешения.
Не включайте фоновые расписания как побочный эффект подключения.
