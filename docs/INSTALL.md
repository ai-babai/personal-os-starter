# Установка и обновление

Python 3.9+; внешние библиотеки не нужны. Интернет нужен для получения шаблона,
но `init` и `check` не обращаются к сети. Git для сгенерированной OS необязателен.

1. Скачать выбранный tag/commit шаблона в отдельный каталог исходников.
2. Ответить на [анкету](../onboarding/OWNER_QUESTIONNAIRE.md) и создать приватный JSON.
3. Выбрать новую папку OS, отдельно от каталога кода и клона шаблона.
4. Проверить план и выполнить установку:

```sh
python3 scripts/personal_os.py init --root "$HOME/personal-os" --profile local/profile.json --dry-run
python3 scripts/personal_os.py init --root "$HOME/personal-os" --profile local/profile.json
python3 scripts/personal_os.py check "$HOME/personal-os"
```

В `code_root` допускается `~` текущего пользователя. Относительные пути и
переменные вида `$HOME` в JSON не поддерживаются; используйте `~` или абсолютный путь.
Остальные поля — непустые однострочные строки; `timezone` — имя IANA или `UTC`.
Установщик использует локальную базу часовых поясов Python; если она отсутствует,
воспользуйтесь `UTC` либо установите системные timezone data отдельно.

`--dry-run` не создаёт каталогов. `init` заполняет файлы в закрытой временной
папке рядом с целью и переносит готовое дерево в новый корень. Каталоги получают
права 0700 и файлы 0600 на POSIX. Промежуточная папка удаляется при обычной ошибке;
после аварийного завершения она может остаться рядом с целью с префиксом
`.personal-os-init-`. Удалять её можно только убедившись, что она относится к
этой незавершённой установке. Существующие файлы и настройки не изменяются.
Корень и его родитель должны быть доверенными локальными каталогами:
не запускайте установку в общей папке, которую могут менять другие пользователи.

Установщик не создаёт `code_root`, не устанавливает клиентов/коннекторы и не
запускает Git. В `.personal-os.json` записаны версия, параметры и исходный
идентификатор содержимого комплекта; это локальные данные новой OS.
`check` проверяет только файлы поставляемого ядра, ссылки между ними и подстановки.
Он не обходит личные заметки, не читает секретные значения, не обращается к
клиентам и не доказывает качество ответов агента. Изменения текста ядра разрешены.

## Ошибки

- `target already exists`: выберите другой новый путь. Повторная установка
  намеренно прекращается, даже если существующая папка пуста.
- Пересекающиеся пути: разнесите OS, исходники шаблона и каталог кода.
- Неизвестные/пропущенные поля JSON: сравните с примером; опечатка не станет настройкой.
- Неподдерживаемый часовой пояс: проверьте имя и локальную базу timezone data.
- Ошибка прав: создавайте OS от её владельца; не используйте `sudo` как общий обход.

## Обновление

В версии 0.1 нет автоматического обновления личной OS. Не запускайте новый `init`
поверх неё и не копируйте всё `workspace/` поверх персональных файлов.
Скачайте новую версию в отдельный каталог, разверните временную чистую OS с теми
же параметрами и сравните нужные документы. Переносите выбранные изменения через
reviewable diff после приватной резервной копии. Сохраняйте профиль, память,
решения, исходные даты и доступы владельца. `check` запускайте из той версии
комплекта, которая записана в `.personal-os.json`.

Откат начальной установки: после проверки отсутствия новых ценных записей удалить
только созданную папку. Глобальных настроек для отката у `init` нет.
