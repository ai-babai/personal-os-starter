# Онбординг для агента

Ты разворачиваешь Personal OS для владельца. Выполняй шаги сам доступными
инструментами; у человека уточняй только недостающие решения. Не отправляй
его читать этот документ или выполнять команды, которые можешь выполнить сам.

**Результат:** личная папка в выбранном месте, фактическая среда в `AGENTS.md`,
минимальный подтверждённый профиль и первый полезный результат.

## 1. Определи исходное состояние

- Найди уже указанный владельцем корень OS. Если он не выбран, уточни его до
  записи личных файлов. Допустим любой путь, в том числе `D:\` или `D:\PersonalOS`.
- Проверь фактические ОС хоста, оболочку и доступ к файлам. При удалённой работе
  ориентируйся на машину с файлами, а не на устройство с интерфейсом.
- Если в выбранном месте уже есть рабочие материалы, прочитай существующие
  инструкции и карту; имена и пути могут отличаться от шаблона.
  - Для обычной задачи продолжи по старой карте с шага 5, без повторной установки.
  - Для перехода на этот стартер открой [миграцию в две фазы](MIGRATION.md).
    Если комплект ещё не получен, сначала выполни шаг 2. Не копируй `workspace/`
    поверх старой OS и не начинай повторное знакомство.
  - Если намерение неясно, уточни: продолжить работу или перенести структуру.

Не сканируй весь диск: соседние папки не входят в OS автоматически.
Если нужного доступа нет, обозначь ограничение и одно конкретное действие
владельца, которое позволит продолжить. Не заявляй о выполненной установке.

## 2. Получи комплект, если его ещё нет

Если нужная версия репозитория уже клонирована или ZIP распакован, используй
эту копию. Иначе получи **main** в отдельный каталог для исходного шаблона.
Если в поручении задан commit или другая ветка, используй именно их:

| Условие | Действие |
|---|---|
| Git доступен | Выполни команду ниже из каталога для исходников |
| Git отсутствует | Скачай [ZIP ветки](https://github.com/ai-babai/personal-os-starter/archive/refs/heads/main.zip) и распакуй доступными средствами ОС |

```sh
git clone --branch main https://github.com/ai-babai/personal-os-starter.git
```

Для заданного commit после клонирования выполни `git checkout <commit>`
в каталоге исходников; вместо ZIP ветки используй
`https://github.com/ai-babai/personal-os-starter/archive/<commit>.zip`.
Ветку можно использовать для знакомства, сравнение агентов фиксирует commit.

Команда подходит для PowerShell и терминалов macOS/Linux. При занятом имени
каталога используй существующую копию этого шаблона или другое свободное имя;
не перезаписывай чужие файлы. Git, Python и Node.js устанавливать ради стартера
не нужно. ZIP содержит те же документы, что Git, без истории `.git`.

Примени [правила исходного репозитория](../AGENTS.md). Для установки достаточно
этого онбординга и входных файлов `workspace/`; продуктовый README и все
справочники подряд читать не требуется.

## 3. Подготовь личную папку

Скопируй **содержимое `workspace/`** в выбранный корень, включая `.gitignore`
и `LICENSE`. Пользуйся средствами обнаруженной ОС; обязательного установщика нет.

Этот шаг — для новой OS. Перенос существующей выполняй по
[инструкции миграции](MIGRATION.md). Для новой установки создаются базовые
разделы `workspace/`; конкретные проекты и подключения — по задаче.

Перед записью проверь совпадающие пути. Добавляй отсутствующее, а существующие
документы дополняй выборочно по смыслу. Сохраняй профиль, память, локальные
правила и настройки клиента. Пустой шаблон не заменяет заполненный документ.
Если конфликт нельзя разрешить без выбора владельца, уточни только его.

Исходный шаблон и личная OS — разные наборы файлов. Не заполняй профиль внутри
репозитория шаблона, не переноси его `.git` и не отправляй личные данные в его
публичный remote. Не меняй соседние папки и настройки существующего репозитория владельца.

## 4. Настрой вход и познакомься

Дальше работай в корне личной OS:

1. Прочитай `INDEX.md`, примени `AGENTS.md` и выполни `system/agent/BOOTSTRAP.md`.
   По карте открывай только область текущего шага.
2. Составь раздел «Локальная среда» в `AGENTS.md`: фактическая ОС хоста,
   абсолютный корень OS и используемая оболочка. Сохрани остальные правила;
   неизвестное отметь явно, версии не угадывай. При переносе перепроверь сведения.
3. Из запроса и существующего профиля возьми уже подтверждённые ответы.
   Одним коротким сообщением уточни только недостающее: как обращаться к
   владельцу, язык и стиль общения, первую задачу. Не задерживай полезную
   работу ради необязательных ответов. Запиши подтверждённое в
   `personal/profile.md` и `personal/preferences.md` с датой и основанием.
   При заполнении заменяй противоречащие данным стартовые заглушки.
4. Если требуется постоянный вход или особенность клиента, открой нужную
   строку [каталога клиентов](../docs/CLIENTS.md). Возьми только соответствующую
   инструкцию из комплекта либо по ссылке той же версии и выполни её локальное
   подключение. Не устанавливай все клиентские пакеты заранее.

Имя и подробную роль агента, личную историю, проекты и инструменты раскрывай
по мере задач. Не переноси личность и настройки автора шаблона. Онбординг сам
по себе не разрешает запуск субагентов, отправку сообщений, подключение аккаунтов
или платные действия.

## 5. Выполни первую задачу и сохрани продолжение

Реши выбранную владельцем задачу в пределах её полномочий. Что сохранять,
определяет [правило передачи](../workspace/system/agent/protocols/handoff.md):
ожидаемые артефакты и изменения состояния задачи, без обязательного документа
на каждый разговор. Не создавай демонстрационный проект ради заполнения папок.

## Проверка результата

- Файлы находятся в выбранном корне; вход через `INDEX.md`, `AGENTS.md` и
  `system/agent/BOOTSTRAP.md` работает, нужные относительные ссылки разрешаются.
- Локальная среда соответствует проверенным фактам; профиль содержит только
  подтверждённое. Существующие знания и правила сохранены.
- Есть результат первой задачи или явно записанный блокер с продолжением.

В конце кратко сообщи владельцу абсолютный путь OS, что настроено, результат
первой задачи и что осталось проверить. Если создан артефакт, дай ссылку на него.
Для следующего чата дай короткий вход:
«Открой [фактический путь], прочитай INDEX.md, AGENTS.md и system/agent/BOOTSTRAP.md,
продолжи по сохранённому состоянию» — подставь реальный путь.

Чтение файлов в текущем чате не доказывает автоматическое подключение нового.
Если новый чат ещё не проверен, так и укажи; не запускай его без полномочий.
