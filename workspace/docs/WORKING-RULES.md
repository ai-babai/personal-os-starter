# Рабочие правила

## Документы

Для нового поддерживаемого Markdown используй YAML `type` (1–40 символов),
`description` (1–240 символов: содержание и условие чтения), `created` как
дату создания `YYYY-MM-DD` в часовом поясе владельца. Сохраняй исходную дату
при правках/переносе. Если у старого документа дата неизвестна, не выдумывай.
Чужие исходники, внешние навыки и сырые импорты не переписывай под этот формат.

У каждого раздела карта `INDEX.md`; ссылки — относительные. Добавляй новую папку
по задаче. `AGENTS.md` нужен только для действительно отличающихся обязательных
правил. Процедуры и критерии имеют один источник, карты ссылаются на него.

## Источники и память

У выводов указывай источник и дату проверки, отделяй цитату, факт и предположение.
Память не должна превращаться в копию всех чатов. Правило общения относится
к предпочтениям; статус проекта — к проекту; общий порядок работы — к docs.
Периодический уход за памятью/автоматизации вводятся только по отдельному решению.

## Реализация и проверки

Простое решение под текущую задачу предпочтительнее заготовок для будущего.
Проверяй наблюдаемый результат; записывай ограничения. Объём тестов согласуй
с проектным контрактом; не создавай постоянный тестовый набор без потребности.
Тяжёлые данные, модели, datasets и кэши держи вне OS и Git-репозиториев кода.
Не скачивай их без согласованной задачи, места и бюджета.

## Публикация

Публикация личной информации требует отдельного решения владельца.
Материал, существенно написанный агентом для публичного размещения,
должен иметь видимое указание на участие ИИ и подтверждённое происхождение.
Не имитируй личное авторство и пережитый опыт человека.
