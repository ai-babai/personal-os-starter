# Проверки поведения

Как агент начинает знакомство, уточняет задачу и готовит переход на Personal OS.
Здесь собраны сценарии, исходные ответы моделей и разбор наблюдений.

[Сценарии](#сценарии) · [Результаты](#результаты) · [Как повторить](#как-повторить)

Эта область нужна сопровождающим стартера. В личную OS она не копируется.
Установка по-прежнему обходится без тестового инструментария.

Один ответ показывает возможное поведение. Вероятность ошибки и переносимость
между клиентами требуют отдельных повторов. Завершение сессии, качество ответа
и фактическое выполнение установки оцениваются раздельно.

## Как повторить

1. Выбери сценарий и зафиксируй версию стартера. Для локальных изменений сохрани
   diff к базовому commit. Для повторения сохранённого прогона используй его
   `manifest.json` и точный вход из `inputs/`. Критерии той серии сохранены в `rubrics/`.
2. Открой новую сессию выбранной модели без истории других попыток. Передай
   [общее поручение](PROMPT.md), `input.md` и перечисленные в манифесте инструкции.
   Сохрани параметры клиента, точный ID модели и reasoning.
3. Получи первую завершённую реплику. В текстовой симуляции операции с файлами
   и аккаунтами не выполняются. Сохрани ответ дословно после проверки приватности.
4. Оцени ответ по `rubric.md`. Укажи конкретные цитаты, удачные решения и проблемы.
   Все попытки, включая сбои, должны остаться видимыми в отчёте.

Для сборки одного входа есть необязательный помощник на стандартной библиотеке
Python. Он объединяет общий запрос, сценарий и инструкции; критерии оценки
в пакет не попадают. Запросы к моделям помощник не отправляет.

```sh
python3 evals/prepare.py --case existing-folder --source . --output local/example/INPUT.md
```

Передай собранный файл свежей сессии с просьбой прочитать только `INPUT.md`
и вернуть первую реплику симуляции. Точный внешний запрос сохранён в манифесте
прогона. Старый выходной файл помощник не перезаписывает.

Можно использовать любой клиент. В BB каждая попытка запускается отдельной
дочерней сессией с явно заданными моделью, reasoning и названием.
Унаследованные инструкции клиента учитываются как ограничение сравнения.
Новые прогоны, платные запросы и публикация требуют полномочий текущей задачи.

## Как добавить сценарий

Создай папку в `cases/` с двумя файлами: `input.md` и `rubric.md`.
Первый содержит запрос и доступные агенту факты. Второй задаёт несколько
наблюдаемых критериев. При необходимости добавь небольшой синтетический файл.
Укажи сценарий в таблице выше. Меняй критерии до начала новой серии.

Результат серии хранится в `runs/<дата>-<тема>/`: отчёт, параметры, редакция
инструкций и ответы. Для проверки реальных действий потребуется отдельный
сценарий с изолированной рабочей папкой и проверкой её изменений.

## Приватность

В Git допускаются синтетические входы и проверенные отчёты. Частные переписки,
профили, абсолютные пути реальных машин, ID личных сессий, токены и сырые логи
клиента сюда не копируются. Обезличенный разбор пишется заново по проверенным
фактам. Замена одного имени в исходном экспорте недостаточна.

Локальные служебные файлы прогона можно держать в игнорируемой папке `local/`.
Перед включением новых результатов просмотри весь diff и проверь данные внутри
ответов моделей. Автоматический поиск помогает найти подозрительное; итоговый
просмотр выполняется отдельно.
